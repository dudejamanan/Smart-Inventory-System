# Decisions

1. Build at the existing repository root (`D:/inventorySystem`), rather than nesting another repository.
2. Python 3.11 is the supported development runtime (installed locally); Python 3.14 is not used because pinned OpenCV wheels target earlier runtimes.
3. A single FastAPI process owns hardware. Never run multiple Uvicorn workers. SQLite uses WAL, a busy timeout, and short per-operation sessions.
4. UNO owns all buzzer decisions. Serial authentication is sent before database event insertion or camera work. Notification and evidence queues run independently.
5. Simulation uses the real vision pipeline and a clock-injected firmware port; it never claims to measure electrical latency.
6. Demo data is created only in simulation or via the explicit seed command. Blank real installations start without authorized cards.
7. Official references checked on 2026-10-24: [MFRC522](https://github.com/miguelbalboa/rfid), [OpenCV](https://docs.opencv.org/4.x/d5/dae/tutorial_aruco_detection.html), [Twilio request validation](https://www.twilio.com/docs/usage/security), [Twilio 63016](https://www.twilio.com/docs/api/errors/63016). New OpenCV uses ArucoDetector/generateImageMarker; compatibility branches support detectMarkers/drawMarker. Twilio error 63016 means outside the 24-hour service window; this course project uses free-form sandbox messages, not template campaigns.
8. DevRelay community searches and event lookup were attempted but refused because the account is not connected. No community claims or links are fabricated.
9. UI uses React 18 and plain CSS, with the shelf feed as the primary control-desk view. The Vite pin was raised from 6.3.5 to 6.4.5 after npm audit reported advisories; the updated audit reports zero vulnerabilities.
10. Password, cookie secret and media HMAC secret are required in real mode and generated only into .env by the local setup script. Simulation without .env accepts an empty password on loopback for immediate exploration; it uses ephemeral signing keys. Never expose that unconfigured simulation publicly.
11. Notification request pacing also respects Twilio's documented sandbox limit of one message every three seconds; the worker spaces SDK calls by at least 3.1 s. The per-kind 20 s suppression is separate. Approved template messaging outside the service window is deliberately out of scope.
12. Gate incident evidence association runs before and independently of notification processing. An expired WhatsApp window cannot prevent storing or displaying a gate incident photo.
13. The camera ring retains at most five seconds. Clips resample to six seconds around an incident, duplicating nearest available frames if startup/history/network gaps leave insufficient coverage. Codec failure yields individually hashed JPEG frames. Real pre-event coverage depends on the source running before the event.
14. All secrets and connection credentials stay in .env. The settings table exposes nonsecret defaults, including serial/camera options. Serial/camera source and capture-rate changes require restart. Camera URLs containing credentials cannot be saved to settings and are omitted from the settings response. UNO AUTH/watchdog timing constants are compile-time; only CFG fields can change without recompilation. These limitations are explicit rather than silently implying every setting changes firmware remotely.
15. latency_bench.py computes statistics only from actual external-instrument timestamps. It cannot infer physical light/sound timing from simulator or host event messages. Definitions and acquisition instructions are in TEST_PLAN; no measurement CSV or numbers are fabricated.
16. Keep protects original incident evidence and failed-scan photos; retention also protects active empty-reference calibration images. Historical events/rows remain. Filesystem-backed .jpg/.mp4 media beyond retention are deleted locally, so back up important data and mark Keep first.
17. Only one active session is permitted. An expression-based partial unique index coalesces NULL end_ts to a constant, because a plain unique index on nullable end_ts would allow multiple open rows in SQLite. Existing development databases require a schema migration/recreation to change an old index; fresh installations get the correct index.
18. Development port 8000 was occupied by another process, which was left alone. The verified preview uses 127.0.0.1:8123. The normal scripts retain the requested conventional default port; pass --port to the entry point when needed.
